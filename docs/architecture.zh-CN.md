# 工程设计：源码、渲染实例与可视化编辑的对应关系

[English](architecture.md) · [返回项目介绍](../README.zh-CN.md) · [案例推演](../examples/walkthrough.zh-CN.md)

可视化编辑需要完成两个不同的步骤：先确定用户选中了什么，再确定这次操作应当修改什么。
源码位置可以帮助回答第一个问题；值的来源、实例范围和业务归属共同决定第二个问题。

本文将 Foundax 编辑器的工程实践抽象为参考设计。类型与伪代码用于说明边界，
不对应一套已随仓库交付的编译器或运行时。静态案例可用来检查设计是否能解释具体编辑行为。

## 1. 系统拓扑与状态归属

### 1.1 从作者代码到编辑操作

```text
作者入口：Agent / 代码编辑器                 用户入口：可视化画布
          │                                          │
          ▼                                          │ 选择 + 意图 + 范围
可信宿主                                             ▼
  版本化项目 ──► 编译分析 ──► 编辑索引 ──► 编辑目标与能力解析
      ▲              │                               │
      │              ▼                               ▼
      │         派生预览代码                    修改计划与版本校验
      │              │                               │
      └──────────────┼────────────── 原子提交 ◄───────┘
                     ▼
隔离预览运行时：渲染元素 / 调用路径 / 集合成员观测 / 选择事件

业务服务：持有商品等业务事实，通过授权读取提供展示数据
```

宿主接收编辑意图，解析可信索引并执行修改。浏览器报告的 DOM、路径或源码偏移只是输入，
不能直接成为写入地址。构建与预览涉及用户代码时，应在与可信宿主分离的受限环境中执行。

### 1.2 四类状态

| 状态 | 持有内容 | 生命周期与归属 |
| --- | --- | --- |
| 项目版本 | 作者源码、页面引用、显式实例编辑状态 | Agent、代码编辑器和画布操作共同提交 |
| 编译派生数据 | 源码节点、字段来源、编辑索引、预览产物 | 由特定项目版本与工具链生成，可重建 |
| 运行时观测 | 当前渲染出现、调用链、活动分支、选择范围 | 属于当前预览实例，不直接作为持久身份 |
| 外部业务数据 | 商品、价格、库存等 | 由原有业务系统维护，有独立的授权与版本 |

项目版本可以同时包含源码和稀疏的实例覆盖。覆盖记录应有明确的实例、字段及作用范围，
不再保存一份与源码分别更新的完整页面树。编译索引描述项目，不成为另一份可独立修改的页面事实。

### 1.3 预览与发布

预览和发布使用相同的源码、有效实例覆盖及业务绑定解释规则。
选择框、编辑事件和诊断信息属于编辑运行时；实例文案和样式覆盖属于页面效果，发布时也必须生效。
记录项目版本与工具链身份，避免将某次构建的索引用于另一次构建的预览。

## 2. 编译分析：从代码位置到值的来源

### 2.1 编辑索引

编译器读取授权范围内的源文件与模块关系，解析 JSX 节点、字段和引用路径。
索引至少需要表达以下内容：

| 信息 | 用途 |
| --- | --- |
| 项目版本、工具链标识 | 将索引绑定到实际构建输入 |
| 文件标识、内容摘要、源码范围 | 在固定版本内定位与校验修改位置 |
| 节点及字段标识 | 区分一个元素与它的文字、链接、图片等字段 |
| 来源路径（Value Provenance） | 说明值经过哪些变量、参数、调用点或数据绑定 |
| 解析结果与能力条件 | 区分可追踪、动态、外部或歧义来源 |

这些信息由编译过程生成，模型无需逐项维护。
Source Map 负责生成代码与原代码的位置映射；编辑索引进一步表达值与操作的语义。

### 2.2 静态分析与运行时观测分工

静态分析适合追踪字面量、变量引用、可解析的参数传递和受支持的表达式。
它保留候选来源与条件，不通过执行作者函数来猜测任意表达式的含义。

运行时观测帮助回答：当前挂载的是哪个调用点？列表中的哪一个成员？正在呈现哪条分支？
这些观测用于缩小候选范围；宿主仍需结合当前版本的代码与绑定验证它们。
看见某个值在运行时出现，并不证明存在唯一、可逆的写入路径。

插桩应尽量避免额外的布局包裹与表达式求值。
需要验证求值次数、组件调用和展示结果，避免观测代码改变作者程序的行为。

### 2.3 四种身份不能混用

| 身份 | 示例含义 | 能否单独决定持久修改目标 |
| --- | --- | --- |
| 源码节点 | `Note` 定义中的一个 `<h2>` | 只能确定定义位置 |
| 组件调用点 | 页面里的第二个 `<Note />` | 可确定一次源码调用，仍需验证字段来源 |
| 集合成员 | 一条具有稳定业务键或本地身份的数据记录 | 需要结合所属集合与调用路径 |
| 渲染出现 | 当前 DOM 中的一次呈现 | 只能作为当前预览的观察信息 |

React 的 `key` 用于协调列表渲染，不直接承担宿主授权或跨版本编辑身份。
业务 ID 也不能单独代表页面实例：同一商品可以在页面中出现多次，并拥有不同的展示设置。

## 3. 编辑语义：来源、意图与作用范围

### 3.1 先声明操作，再生成修改计划

选择事件和编辑命令可以使用如下简化契约：

```ts
type EditCommand = {
  expectedRevision: string;
  selectionId: string;
  field: string;
  operation: "set-text" | "set-style" | "replace-binding";
  scope: "definition" | "instance";
  value: unknown;
};
```

`selectionId` 是宿主可解析的选择引用，不是客户端提供的任意文件路径。
`scope` 表达用户意图；是否支持该范围由宿主结合索引决定。
具体操作应有各自的值类型与校验规则，上述类型只展示共同字段。

### 3.2 根据值的归属选择写入入口

| 值或属性来源 | 典型操作 | 修改入口 |
| --- | --- | --- |
| 直接 JSX 文案 | 修改页面标题 | 当前版本中已定位的文案字面量 |
| 独立调用点的字面量参数 | 修改第二张提示卡 | 该调用点参数，保留其他调用点 |
| 多处共享的组件定义 | 修改所有同类组件 | 明确的定义级源码修改 |
| 需要独立外观的实例 | 仅调整当前卡片颜色 | 已证明实例身份下的稀疏覆盖，或明确的实例参数 |
| 页面商品引用 | 更换展示商品 | 页面引用或查询参数，保留组件展示代码 |
| 商品价格等外部字段 | 修改真实售价 | 业务服务的授权操作 |
| 格式化、聚合等派生值 | 修改计算后的显示结果 | 选择输入或表达式的显式编辑入口 |

不能唯一确定来源时，编辑器可以显示候选位置和作用范围，让用户明确选择。
没有受支持修改入口的表达式仍可显示与定位，其直接值修改能力应明确标为不可用。

### 3.3 实例覆盖的状态模型

源码提供默认表现，实例覆盖表达用户明确选择的局部差异。
覆盖至少记录稳定实例路径、字段、作用范围和覆盖值，并与项目源码一起版本化。

这会引入额外责任：定义默认值与覆盖的合成顺序；实例被移除时处理其覆盖；
Agent 调整结构后重新验证覆盖目标；导出和发布时保留覆盖效果。
覆盖不能只依赖当前 DOM 的顺序，否则重新排序或增加包裹后就可能作用到其他元素。

**身份仍然存在，不代表旧覆盖仍然适用。** 一份覆盖还依赖字段的来源和当时的基础值。
例如，Agent 已明确修改同一处作者文案，旧的实例文案不能仅凭节点 ID 相同就继续遮住新内容。
因此重新解析覆盖时，还应检查来源路径、字段语义与基础值，保留无关覆盖，撤下已失效的覆盖并记录原因。
具体哪些代码修改会使覆盖失效，应成为显式规则，并用连续编辑案例验证。

## 4. 从编辑命令到版本化提交

### 4.1 修改流水线

```text
验证请求与权限
  → 检查基准版本
  → 用该版本索引解析选择及作用范围
  → 准备源码修改、实例覆盖或引用变更
  → 校验候选项目
  → 比较并交换项目版本（CAS）
  → 生成并加载新版本的预览与索引
```

源码修改应针对解析后的节点或准确范围生成，保留与目标无关的代码。
提交前检查原内容与版本；多处修改先全部准备，再作为一次项目变更提交。
使用源码补丁或 AST 转换均可，重点在于目标明确、变化可检查、失败不部分写入。

```python
def apply_edit(principal, project_id, command):
    authorize_project_edit(principal, project_id)
    validate_command(command)
    current = read_project_head(project_id)
    require_revision(current, command.expectedRevision)

    index = require_edit_index(current.revision, current.toolchain)
    target = resolve_selection(index, command.selectionId)
    plan = prepare_edit(current, target, command)
    candidate = apply_plan(current, plan)
    validate_candidate(candidate)

    return commit_if_head(project_id, current.revision, candidate)
```

`prepare_edit` 验证来源与范围，并产生明确修改计划；`commit_if_head` 在持久化边界原子检查版本。
中间读取到的版本检查不能代替提交时的比较并交换。
新索引尚未就绪时，应暂缓依赖新索引的编辑请求，避免把新预览与旧索引组合使用。

### 4.2 源码修改与业务写入分开提交

替换页面中的商品引用属于项目修改，可以与页面样式一起保存。
修改商品价格属于业务系统，使用业务服务自己的权限、校验和并发控制。
两者不共享一套通用的源码补丁事务；产品交互应明确区分它们的结果与撤销含义。

页面呈现可以由“项目版本 + 当前授权业务视图”共同决定。
在采用实时业务读取的系统中，撤销页面引用应恢复先前引用，随后读取该商品的当前数据；
它不会恢复历史售价，也不会撤销库存变更。预览与发布应遵循相同的绑定语义，数据刷新频率由读取策略决定。
一个具体过程见 [案例推演第 5 节](../examples/walkthrough.zh-CN.md)。

## 5. Agent 改代码后的身份延续

### 5.1 偏移位置与稳定身份

文件范围能够准确定位一个固定版本内的节点。插入一段 JSX 后，后续偏移可能全部变化。
稳定身份用于延续编辑语义，具体修改仍必须通过新版本索引重新解析位置。

身份协调可以结合已有身份、模块与调用关系、父级上下文、结构对应关系和明确的成员键。
文本相同或样式相同只能提供候选信息，不能单独证明是同一个对象。

### 5.2 可确认的延续与未解析状态

| 代码变化 | 处理原则 |
| --- | --- |
| 修改不相关函数 | 重新生成位置索引，保留可确认的目标身份 |
| 移动一个可唯一对应的子树 | 保留身份，更新位置与上下文 |
| 复制一张卡片 | 为新对象分配独立身份，明确覆盖是否复制 |
| 多个相同节点重排且无可区分身份 | 将受影响映射标记为未解析，要求重新定位 |
| 删除实例或更换数据来源 | 检查原覆盖与绑定是否仍适用 |
| 旧画布提交修改 | 拒绝陈旧版本，加载新状态后重新生成修改 |

身份延续的范围必须与可验证的对应关系一致。
对于未解析的覆盖，保留其诊断与原版本信息，先解除其对新目标的应用，待重新确认后恢复。
这样可以避免把旧实例的文案或外观静默移到另一个实例。

## 6. 工程成本与可观测性

| 机制 | 收益 | 成本与取舍 |
| --- | --- | --- |
| 编译派生编辑索引 | 模型按普通源码创作，平台集中维护编辑信息 | 解析、模块分析、索引体积与工具链适配 |
| 值来源追踪 | 将字段修改指向实际来源 | 分析覆盖范围、分支数量与歧义处理 |
| 运行时实例观测 | 区分共享定义的实际呈现 | 插桩开销与运行行为一致性验证 |
| 显式实例覆盖 | 局部修改无需复制完整组件 | 合成规则、迁移、撤销及发布一致性 |
| 项目版本与 CAS | 防止 Agent 和画布互相覆盖 | 冲突处理与索引重新准备 |

同一项目版本与工具链的索引可以复用；修改后的局部重分析需要完整的依赖追踪，
不能因为只改了一个文件就假定其他调用点的来源没有变化。

建议分别记录解析、来源分析、插桩、预览更新与提交的耗时，并观察：
可解析字段比例、实例范围可确认比例、歧义目标数、身份延续情况与陈旧版本拒绝数。
耗时下降应与编辑正确性一起评估，不能通过错误扩大可写范围换取更高的“可编辑率”。

## 7. 验收矩阵

下面是供实现者使用的验收要求，不代表本仓库交付了对应执行测试。

| 场景 | 应验证的结果 |
| --- | --- |
| 修改直接文案 | 只改目标字面量，保留周围 JSX 与表达式 |
| 两个调用点显示相同文案 | 修改第二个时第一个保持不变 |
| 修改共享定义 | 所有受影响实例符合用户选择的范围 |
| 替换商品引用 | 展示内容随引用更新，原商品记录不变 |
| 修改格式化价格 | 不将计算结果错误固化为页面文案 |
| 重排可识别的列表成员 | 相关编辑状态跟随成员，未交换身份 |
| Agent 插入节点后提交旧选择 | 拒绝旧版本，不按旧偏移写入 |
| 实例覆盖保存并发布 | 重新加载、撤销和发布保持相同的状态解释 |
| 打开或关闭编辑插桩 | 在相同输入下保持作者程序的预期行为 |
